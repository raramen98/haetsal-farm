# 기획서 — 햇살농원 주문·출고 관리

> 고객사: 15. 농산물 직거래 농가 "햇살농원" · 작성: 해라 · 2026-11-13
> 근거: 요구사항 정의서(FR-ID), `N` = 노션 인터뷰, `I#` = 인터뷰실 질문 번호

---

## 1. 한 줄 요약

**세 경로로 들어온 주문을 전화번호 기준으로 한곳에 모으고, 남은 수량과 발송 규칙을 시스템이 지켜 주는 농가용 주문·출고 관리 웹앱**

- 목표: 정우 씨가 "누구에게, 무엇을, 언제 보낼지"를 머리로 맞추지 않게 한다
- 성공 기준: 명절 전 하루치 주문(카톡·전화·스마트스토어)을 모아 **초과 주문 0건**, **오늘 보낼 목록이 자동으로** 나온다

## 3. 핵심 흐름

```
주문 입력 (엑셀 / 카톡 / 전화)
  → 전화번호로 고객 묶기 (번호 없으면 '번호 확인 필요', 중복이면 '중복 의심')
  → 남은 수량 확인 (넘으면 저장 거부, 판매 전이면 '예약')
  → 발송 예정일 자동 계산 (3시 마감·월~목·입금 확인·판매 시작일)
  → 오늘 보낼 목록 → 어머니 포장 목록 → 3시 택배
```

## 6. 범위를 이렇게 나눈 기준

1. **기본 요구사항 6개는 모두 P0**: 심사의 출발점이자 고객이 명시한 것
2. **"주문이 들어와서 택배로 나가기까지" 한 흐름이 끊기지 않게**: 입력만 되고 출고가 안 되면 실제로 쓸 수 없음
3. **가산점은 인터뷰 근거가 강한 것만**: 고객이 불편을 직접 말한 것(발송 규칙, 카톡 주문, 문자 쓰기)
4. **고객이 "기준 없음"이라 한 것은 기본값만 두고 설정으로**: 정책을 대신 정하지 않음
5. **외부 연동은 전부 제외**: 5시간 안에 배포까지 마치는 것이 우선

## 7. 시연 시나리오 (발표 10분 중 약 5분)

1. **아버지** 로그인 → 부사 선물용 판매 한도 10박스, 판매 시작일 10/25 입력
2. **정우 씨** → 스마트스토어 가상 엑셀 업로드 → "김순자 / 순자 어머님" 같은 번호로 묶임, 카톡과 같은 주문은 `중복 의심`
3. 카톡 문장 붙여넣기("부사 선물용 2박스씩 다섯 군데…") → AI가 배송지 5곳 초안 → 저장
4. 한도를 넘는 주문 → **저장 거부** 확인
5. 고객 상세 → 작년 주문 "다시 넣기"
6. 목요일 16시 주문 → 발송 예정일 **월요일** 자동 계산, 입금 전 주문은 오늘 목록에서 빠짐
7. **어머니** 로그인 → 포장 목록(선물용 강조) / 재고 수정 시도 → **권한 거부**
8. 답장 도우미: "사과 냉장고에 넣어야 해요?" → 농원 쪽지 근거로 답, 자료에 없는 질문 → "확인 필요"
9. 배송 사고 접수(사진) → 재발송 → 재고 차감

## 8. 준비할 시험 자료 (고객 상황에 맞춘 가상 데이터)

- 상품: 홍로·부사(사과), 신고(배), 수미(감자) × 선물용/가정용 × 규격 — 가격은 가상
- 고객 30명, 지난해 주문 100건 (같은 번호·다른 이름, 다주소 주문 포함)
- 스마트스토어 주문 엑셀 20건 (카톡과 중복 1건 포함)
- 카톡 주문 문장 8개 (단일 주소, 다주소 5곳, "작년이랑 같은 걸로", 번호 없음)
- 농원 안내 쪽지 6장(품종별 텍스트) + 농업기술센터 자료 발췌본(쪽 번호 포함) — 서로 내용이 다른 항목 1개 이상
